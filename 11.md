What is LLM Gateway?
LLM Gateway (LLM GW) is a centralized service that orchestrates requests to Large Language Models (LLMs), manages conversation history, and integrates additional functionality (enrichments, ratings, etc.) in one unified pipeline.

Key Benefits
Single Point of Access: Product teams interact with multiple LLM providers (e.g., OpenAI, Fireworks) through a single, consistent API.
Context & Persistence: Stores messages in threads, maintaining conversation context across multiple turns.
Enrichment Integration: Automatically applies reusable enrichments (e.g., query understanding) before and after sending requests to the LLM.
Feedback & Analytics: Collects ratings on LLM responses for continuous improvement, usage tracking, and model evaluation.
Why it Matters
Simplifies development as teams no longer need to handle separate integrations with each LLM provider.
Ensures consistency in how LLM requests, data enrichment, and user feedback are managed across Upwork.
Adding LLM Gateway to a Service
1. Get a service and environment specific AI Platform API Key
AI Platform API Key's have the advantage of identifying the team which is issue the request. The key can be further used to indicate the specific client or service. Key's are issued per environment. For more information see Request an API Key

2. Authenticate (client-side token exchange)
The primary path is to exchange your AI Platform API key for a short-lived JWT, then call LLM Gateway with that JWT.

Step 1 — Exchange your API key for a JWT (Key Manager):

curl -X POST 'https://ai.staging.platform.usw2.upwork/v1/auth/token' \
  --header 'X-API-Key: <AI Platform API Key>'
The response includes an access_token JWT.

Step 2 — Call LLM Gateway with the JWT:

Authorization: Bearer <jwt>
See Key Manager for details on token exchange and Request an API Key to obtain a key.

Gateway fallback
LLM Gateway also accepts the API key directly via X-API-Key: <AI Platform API Key>. Prefer the client-side exchange above; use X-API-Key only when you intentionally want the gateway fallback path.

3. Add USI Core to environment repository allow list
In your application's service-mesh-environment platform.yaml file ensure the dependency is included.

Example:

upstreamDependencies:
  - usiCore 
4. Configure your application to use the LLM Gateway's base URL
Context	Base URL
Local development, targeting staging	https://ai.staging.platform.usw2.upwork/llm-gateway
Local development, targeting production	https://ai.prod.platform.usw2.upwork/llm-gateway
Intra-cluster (deployed services)	https://ai.upwork/llm-gateway
Example for local development against staging:

LLM_GATEWAY_ADDR=https://ai.staging.platform.usw2.upwork/llm-gateway

Core Concepts
Chat Completions
Definition: A request-response process where a Large Language Model (LLM) generates text based on a conversational prompt.

Why it Matters: Chat completions power interactive user experiences—chatbots, Q&A interfaces, or multi-step workflows—by letting the model maintain context over multiple turns.

Key Idea: You send a message (the user's question or statement) to the LLM, and it completes the response like a human conversation.

Example:

User: "How do I create a simple website?"
LLM Chat Completion: "You can start by choosing a platform like WordPress or Wix..."

Messages
Definition: Individual pieces of text in a conversation—either from the user, the assistant, or system-level instructions.

Roles:

User: The person asking questions or providing input.
Assistant (LLM): The model-generated responses.
System/Context: Overarching instructions or constraints that guide the LLM.
Threads
Definition: A collection of messages that form a conversation over time.

Why it Matters:

Maintains context across multiple turns, so the LLM can remember previous questions and answers.
Simplifies how we store and retrieve entire conversations.
Example:

Thread ID 1234 might contain 5 user messages and 5 assistant replies, all part of a single "session."

Turns
Definition: A chat completion and its response

Turns provide ordering and pairing information for chat completion requests and their responses within a thread.

Examples:

The first completion on a thread is turn 0
Susbequent chat completions on the same thread will increase by 1
Enrichments
Definition: Automated or custom transformations added to user messages or LLM responses to improve the conversation flow.

Examples:

Query Understanding: Deciding which knowledge base or API to call based on the user's question.
Content Filtering: Checking user input for harmful or disallowed content.
Memory Retrieval: Automatically pulling user's past preferences or data to provide richer context.
Include History N: Provide up to N number of previous turns including user/assistant interactions in current request for additional context.
Why They Matter:

Consistency: Avoid duplicating the same logic (e.g., checking for prohibited content) in every application.
Customization: Product teams can add domain-specific steps, like searching a help center or retrieving user profile data, all before or after the LLM processes the message.
Ratings
Definition: Feedback scores (like stars, thumbs up/down, or numeric scales) that users or QA teams attach to LLM-generated messages.

Purpose:

Quality Control: Understand how well the LLM performed on a given response.
Continuous Improvement: Identify patterns in good/bad answers, refine prompts or retrain models.
Example:

A user sees the assistant's response and clicks a Thumbs Up. The system stores the rating with the message for later analytics.

Architecture Overview

Supported Endpoints
LLM Gateway provides a unified interface that abstracts over multiple LLM providers, enabling consistent access to advanced capabilities such as request routing, load balancing, caching, and observability—all without requiring changes to client-side integrations. It eliminates provider-specific implementation details, allowing teams to work with a normalized API while still benefiting from the unique strengths of each underlying model. For advanced use cases or model-specific endpoints not yet supported in LLM Gateway, direct access is available through our LLM Proxy, ensuring full flexibility and compatibility with any provider-specific features or custom configurations.
