## 通用代码修复

- `Code/PII/phase2_plan.py`
  - 精确槽位允许修改保留短语中的局部值；不再同时要求“整句原样保留”和“替换其中一词”。
- `Code/PII/phase3_rewrite.py`
  - 项目名只出现在完整 URL 内时，由外层 URL 映射负责，不要求额外输出一次项目名。
  - 槽位位于已合成实体内部时，由实体整体替换负责，不重复检查内部版本号或日期。
  - 计划的新值本身是完整 PII 形状时，在原始候选文本上验证它是否出现。
  - 旧 URL 是计划新 URL 的前缀时，只要旧值仅存在于完整新值内部，就不判为残留。
- `Code/PII/phase6_render.py`
  - Phase 6 使用与 Phase 3 相同的“计划新值覆盖旧值前缀”判据，避免最后审计误报。
- `Code/pii_refresh_text_tasks.py`
  - 重建 Agent 任务时读取 `resolved_buckets.json`，避免把已经提升为 `SHORT` 的
    PII 消息错误地恢复为 `PRESERVE_SHORT`，从而生成过期 plan-slice hash。
- `Code/pii_prepare_offline_text_repairs.py`
  - 离线候选生成器同步采用实体包含、槽位包含和计划值保护规则。
  - 已生成的新 URL 不会因包含旧 URL 前缀而被反复替换。
- `Code/pii_prepare_phase2_offline_repairs.py`
  - 为本次审计项目记录重复 URL 合并、联系页从属关系和短仓库标识的确定性修复。
